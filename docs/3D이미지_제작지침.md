## 1. 무엇에 쓰는 그림인가

교실용 퀴즈 보드게임 **보물섬 점령전**의 선생님 화면(교실 TV/프로젝터)에 띄운다.
보드 좌우 빈 자리를 팀별 무대로 쓰고, 그 무대에 이 그림이 한 장씩 올라간다.

```
┌─────────────────────────────────────────────────────────────┬────────┐
│ ┌─────────────────────────────────────────────────────────┐ │ 홍팀 12│
│ │  ┌────────┐   ┌──────────────────┐   ┌────────┐         │ │ 청팀  9│
│ │  │        │   │  A B C D E F G H │   │        │         │ ├────────┤
│ │  │ 홍팀   │   │1 ? ? ? ? ? ? ? ? │   │ 청팀   │         │ │ 학생   │
│ │  │  3D    │   │2 ? ? ▩ ? ? ? ? ? │   │  3D    │         │ │ 16명   │
│ │  │ 그림   │   │3 ? ? ? ? ? ? ? ? │   │ 그림   │         │ ├────────┤
│ │  │        │   │  … 12줄 …        │   │        │         │ │ 버튼들 │
│ │  │ 480px  │   └──────────────────┘   │ 480px  │         │ │        │
│ │  └────────┘                          └────────┘         │ │        │
│ └─────────────────────────────────────────────────────────┘ │        │
└─────────────────────────────────────────────────────────────┴────────┘
     ↑ 왼쪽은 항상 홍팀              ↑ 오른쪽은 항상 청팀
```

- 자기 차례인 팀 무대 → **수색 그림**이 좌우로 흔들리며 움직인다.
- 차례가 끝나면 → 그 턴에 있었던 일(**보물 / 공격 / 폭풍**)이 그 자리에 올라간다.
- 그림 여러 장이 2.5초마다 번갈아 뜬다.

**그래서 중요한 것 두 가지.**

1. **8장이 같은 아이여야 한다.** 왼쪽과 오른쪽에 딴 사람이 서 있으면 연출이 통째로 싸구려가 된다.
2. **8장의 크기와 위치가 같아야 한다.** 2.5초마다 바뀌는데 크기가 들쭉날쭉하면 화면이 튄다.

## 4. 진행 순서

```
STEP 1  스타일 결정 ...................... ✅ A안 = 픽사풍 3D 카툰
STEP 2  fx_search-C 한 장 ................ ✅
STEP 3  나머지 6장 ....................... ✅
STEP 4  8장 대조 ......................... ✅ 2026-08-10 통과
STEP 5  WebP 변환 · 배치 ................. ✅ 합계 1.5MB
```

> **8장 모두 완료됐다.** 아래 프롬프트는 **한 장을 다시 뽑아야 할 때** 쓴다.
> 그때도 다른 7장은 건드리지 않는다.

**STEP 2를 한 장만 먼저 뽑은 이유** — 팀 색만 바꿨을 때 캐릭터가 유지되는지가 거기서 판가름 난다.
안 되면 6장을 뽑아도 다 버린다. **7장 다 뽑고 나서 틀린 걸 발견하는 게 제일 비싸다.**
다시 만들 일이 생겨도 이 순서를 지킨다.

## 5. 도구 사용 요령

### 참조 이미지를 넣을 수 있는 도구라면 (가장 좋다)

`img/fx_search-H.png`(홍팀 수색)를 **첨부하고**, 아래 프롬프트 **맨 앞에** 이 줄을 먼저 붙인다.

```
Use the attached image as the exact character reference. Keep the same face, hat, hair,
clothes, backpack, proportions and overall scale. Change ONLY what the ACTION line says.
```

해당하는 기능 이름은 도구마다 다르다 — `character reference`, `이미지 편집`, `image-to-image`,
`이 그림을 참고해서` 무엇이든 **가장 강하게 잠기는 것**을 쓴다.

### 대화형 도구(ChatGPT·Gemini 등)라면

**같은 대화창에서 8장을 이어서 만든다.** 창을 새로 열면 캐릭터가 바뀐다.
2번째 그림부터는 이렇게 시작해도 좋다 — `앞의 아이 그대로, 동작만 바꿔줘.` 그리고 프롬프트를 붙인다.

### 참조 기능이 전혀 없다면

아래 프롬프트의 **CHARACTER LOCK 문단이 그 역할을 한다.** 실제로 나온 그림을 보고 받아 적은 것이라
꽤 잘 잡힌다. 다만 seed 고정이 가능하면 같이 쓴다.

### 부정 프롬프트를 받는 도구라면

```
text, letters, watermark, logo, frame, border, multiple characters, two people, crowd,
weapon, gun, blood, scary, sad, realistic photo, cropped head, cropped feet
```

### Midjourney

프롬프트 끝에 `--ar 1:1 --style raw` 를 붙인다. 참조는 `--cref <이미지 URL> --cw 100`.

## 7. 뽑고 나서 볼 것 (한 장마다)

| 확인 | 안 되면 처방 |
|---|---|
| 얼굴이 정면으로 보이는가 | 교실 뒤에서 볼 그림이다. 옆·뒷모습이면 `face clearly visible, looking toward the camera` 강조 |
| 한 명만 있는가 | 부정 프롬프트에 `multiple characters, two people` |
| 팀 색(스카프 + 모자 띠)이 눈에 띄는가 | `a very large RED neckerchief` 처럼 `very large` 를 붙인다 |
| 글자·워터마크가 없는가 | 있으면 무조건 재시도. 부정 프롬프트에 `text, letters, watermark` |
| 인물이 세로 90%를 채우는가 | 작으면 `full body filling the frame, minimal empty margin` |
| 모자나 발이 잘리지 않았는가 | 잘리면 `full body, nothing cropped, head and feet fully inside the frame` |
| 배경이 투명한가 | 흰 사각형이 보이면 다시. 도구가 못 하면 `flat solid cream #fffdf5` 로 바꾼다 |
| 앞 장과 같은 아이인가 | 모자 모양 · 곱슬머리 · 스카프 매듭 · **배낭의 삽** 네 가지를 본다 |

**소품이 안 살아날 때**

| 문제 | 덧붙일 말 |
|---|---|
| 탐지기가 그냥 막대기로 나온다 | `a metal detector with a large round glowing disc head at the bottom` |
| 보물상자보다 상자가 더 크게 나온다 | `the chest is small, the boy is the main subject and much larger` |
| 폭풍이 무섭게 나온다 | `comical and funny, cartoon rain, he is having fun, not in danger` |
| 깃발이 안 보인다 | `a large flag on a tall pole, the flag cloth clearly visible` |

## 8. 다 만든 뒤

1. 8장을 `img/` 에 §2 표의 이름으로 저장한다 (`fx_search-C.png` 처럼).
2. 8장을 한 화면에 늘어놓고 **얼굴·모자·옷·배낭·크기**를 하나씩 대조한다.
   하나라도 어긋나면 **그 장만** 다시 뽑는다(다른 장은 건드리지 않는다).
3. 이후 처리는 개발 쪽에서 한다 — **1024px 그대로 WebP 로 변환**해
   `cloudflare-v2/public/assets/fx/search-H.webp` 형태로 넣는다.
   **원본 PNG 는 `img/` 에 그대로 남겨 둔다.**

```bash
# 저장소 뿌리에서
python3 -c "
from PIL import Image
for n in ['search-H','search-C','treasure-H','treasure-C','storm-H','storm-C','attack-H','attack-C']:
    Image.open(f'img/fx_{n}.png').convert('RGBA').save(
        f'cloudflare-v2/public/assets/fx/{n}.webp','WEBP',quality=92,method=4)
"
```

> ⚠ **청팀 그림은 좌우로 뒤집어 보관한다.** 생성 도구는 여덟 장을 모두 오른쪽을 보게 그린다.
> 청팀 무대는 보드 **오른쪽**에 서므로, 그대로 두면 **화면 밖으로 걸어 나가는 그림**이 된다.
> 뒤집으면 두 팀이 보드(섬 가운데)를 향해 마주 본다. `img/fx_*-C.png` 자체가 이미 뒤집혀 있고,
> **새로 뽑은 청팀 그림은 반드시 한 번 뒤집어서 넣는다.**
>
> ```bash
> python3 -c "
> from PIL import Image
> p='img/fx_search-C.png'
> Image.open(p).transpose(Image.FLIP_LEFT_RIGHT).save(p)"
> ```

> **왜 PNG 로 뽑고 WebP 로 넣는가** — 생성 도구는 PNG(투명)를 주고, 그게 손실 없는 원본이라
> 나중에 다시 뽑을 필요가 없다. 배포본은 크기가 중요하다. 같은 1024px에서
> **PNG 6.5MB → WebP 1.5MB** 로 줄었고 화면에서 차이가 안 보인다(2026-08-10 실측).
