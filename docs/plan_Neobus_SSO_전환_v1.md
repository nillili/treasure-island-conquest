# Neobus SSO 전환 및 기존 퀴즈 백업 실행 계획

작성일: 2026-09-23 (KST)  
상태: **계획 작성 완료 / 구현·운영 조회·백업·삭제·배포는 아직 하지 않음**  
대상: `보물섬점령전/cloudflare-v2`  
이 문서의 경로는 별도 표시가 없으면 `보물섬점령전/` 기준이다.

## 1. 사용자 요구와 확정 범위

사용자가 요청한 것은 다음과 같다.

1. 이 프로젝트의 자체 회원가입·비밀번호 로그인을 없앤다.
2. Neobus에서 로그인한 **선생님만** 교사 기능을 사용한다.
3. 기존 사용자는 정리하고 새 인증 방식으로 시작한다. 현재 사용자는 3명이라고 전달받았다.
4. 등록된 퀴즈는 **전부 백업**한다. 사용자가 세 선생님에게 직접 전달할 수 있다.
5. 전달용 백업은 **`선생님이름/엑셀모음/`** 형태로 만든다. 사용자 확인에 따라 퀴즈 파일 형식은 **`.csv`**로 한다. 폴더 이름은 요청대로 유지한다.
6. 다른 세션에서 실행할 수 있도록 이 문서에 구현·검증·전환·복구 순서를 남긴다.
7. 사용자 설명에 따르면 현재 최고관리자는 **김선생님**이다. SSO 전환 후에도 같은 분이 최고관리자 권한을 이어받도록 한다. 운영 DB의 기존 계정과 대응하는 Neobus 고유 ID는 아직 확인하지 않았다.

이번 세션의 요청은 계획 문서 작성이다. 이 문서를 읽었다는 이유만으로 운영 삭제를 시작하지 않는다. 다음 세션에서 실행을 요청받으면 기존 요구를 이어받아 준비·구현·검증을 진행한다. 이미 정해진 설계 선택을 반복해서 묻지 말고, 실제 관리자 계정·운영 대상 등 확인할 수 없는 필수 정보만 확인한다.

삭제 범위는 **v2의 기존 교사, 세션, 퀴즈, 방, 수업 기록과 해당 방의 내부 저장 데이터**로 정의한다. 퀴즈는 먼저 전달용·복구용으로 백업한다. Neobus 계정·데이터, v1 Apps Script판, 소스 코드, 이미지·음원은 삭제 대상이 아니다. 백업 자체도 삭제 대상에 넣지 않는다.

학생은 지금처럼 **방번호 + 이름**으로 입장한다. 학생에게 Neobus 로그인을 요구하지 않는다. 교사 3명은 백업 대상에 대한 설명이며, 향후 이용자를 이 3명으로 제한한다는 뜻은 아니다. 기본 이용 자격은 승인된 Neobus 교사 전체다.

## 2. 판단 근거와 참고 자료

**구현 가능하다.** 현재 교사 인증이 게임 규칙과 분리되어 있고, Neobus 문서에는 인가 코드·PKCE·연결 토큰·사용자 확인 경로가 정의되어 있다. 다만 문서와 로컬 소스를 검토한 결과이며, Neobus 운영 서버의 설정·응답 및 실제 3명/퀴즈 수는 아직 확인하지 않았다.

### 2.2 현재 코드에서 확인한 사실

| 위치 | 현황 및 변경 이유 |
|---|---|
| `cloudflare-v2/src/auth.ts` | 자체 가입·PBKDF2 비밀번호·12시간 쿠키 세션. 교사 인증의 주 변경 지점 |
| `cloudflare-v2/src/index.ts` | `/api/*` 라우터. `/auth/*` 분기 추가 필요 |
| `cloudflare-v2/src/quizsets.ts` | 모든 퀴즈에 `teacher_id` 소유권 검사. CSV 내려받기는 이미 있음 |
| `cloudflare-v2/src/quiz.ts` | 한 퀴즈 최대 80문항, 보기 2~4개, 정답 내부값은 0부터 시작 |
| `cloudflare-v2/src/quiz.ts`의 `parseCsv` | CSV의 BOM·따옴표·줄바꿈 처리. 백업 재검증에 사용 |
| `cloudflare-v2/src/rooms.ts` | 쿠키에서 교사 ID를 읽어 DO에 전달. 방 목록도 교사별 분리 |

| `cloudflare-v2/src/admin.ts` | `is_super`로 관제 권한 검사. 자체 비밀번호 재설정 제거 필요 |
| `cloudflare-v2/src/sweep.ts` | 자동 정리에는 처리 개수 제한과 실패를 삼키는 경로가 있어 일괄 삭제 증거로 사용 불가 |

| `cloudflare-v2/migrations/0003_admin_and_records.sql` | 수업 기록도 교사 삭제에 종속됨 |
| `cloudflare-v2/wrangler.jsonc` | `run_worker_first`가 현재 `/api/*`만 포함 |
| `cloudflare-v2/test/`, `tools/` | 기존 가입·비밀번호 로그인에 의존하는 테스트와 감시 도구가 있음 |

현재 설정 파일에 기록된 운영 대상 후보:

```text
Worker: treasure-island-v2
D1 binding: DB
D1 database_name: treasure
D1 database_id: e8c1a648-ab37-48e6-be80-91524778e418
Durable Object binding/class: ROOM / RoomDO
```

이는 실행 전 확인용 기준값이다. 현재 Cloudflare 계정, 실제 배포 버전, 사용자 도메인이 일치하는지 먼저 조회한다. `workers.dev` 전체 주소나 Neobus 저장소 위치는 추측하지 않는다.

### 2.3 공식 문서로 확인한 플랫폼 동작

- 인증 콜백은 정적 자산 처리보다 Worker가 먼저 받아야 한다. [Worker 우선 라우팅](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/)
- D1은 SQL 파일로 전체 내보내기·가져오기를 지원하며, 내보내는 동안 다른 DB 요청이 차단될 수 있다. 수업 중에 실행하지 않는다. [D1 가져오기·내보내기](https://developers.cloudflare.com/d1/best-practices/import-export-data/)
- D1 외래키와 CASCADE는 별도로 고려해야 한다. `defer_foreign_keys`를 CASCADE 방지나 삭제 복구 기능으로 생각하지 않는다. [D1 외래키](https://developers.cloudflare.com/d1/sql-api/foreign-keys/)
- 여러 DB 변경을 하나의 원자적 단위로 실행할 때는 D1 `batch()`의 트랜잭션 동작을 이용한다. [D1 Database API](https://developers.cloudflare.com/d1/worker-api/d1-database/)

실행 시 설치된 Wrangler와 최신 공식 문서를 다시 대조한다. 기존 프로젝트 의존성을 이 작업과 무관하게 일괄 업그레이드하지 않는다.

## 3. 최종 사용자 흐름

```text
Neobus 로그인
  → Neobus의 보물섬 점령전 링크
  → 이 프로젝트 /auth/start
  → Neobus /merge/authorize
  → 기존 로그인 확인 및 연결하기
  → 이 프로젝트 /auth/callback
  → 서버에서 코드 교환 + 현재 사용자 확인
  → 승인된 교사만 내부 프로필 자동 생성/갱신
  → 교사 홈
```

- Neobus 메뉴 링크는 게임의 `/auth/start`를 가리킨다. 게임 첫 화면의 선생님 버튼도 같은 경로로 이동시킨다.
- Neobus에 로그인하지 않았으면 Neobus에서 로그인한다. 이 프로젝트가 Neobus 비밀번호를 입력받거나 중계하지 않는다.
- 현재 문서상 `연결하기` 확인 화면은 남는다. 무확인 자동 연결까지 구현된 것으로 설명하지 않는다.
- 콜백 성공 뒤 교사 홈으로 진입하도록 한다. 루트로 보내놓고 학생/교사 선택 화면에 멈추지 않도록 기존 `app.js` 초기화와 연동한다.
- 실패하면 이유와 다시 로그인 버튼을 제공한다. 취소·만료·Neobus 장애를 무한 리다이렉트로 처리하지 않는다.
- 등록 절차는 없지만, 퀴즈 소유권을 위한 최소 교사 프로필은 D1에 자동 저장한다.

## 4. Neobus 쪽 준비

### 4.1 운영에서 확인할 값

- 문서의 `0040_merge_auth.sql` 적용 여부.
- 인가 경로와 `/api/merge-auth/token`, `/me`, `/revoke`의 실제 코드·응답.
- 실제 `user_type`, `approval_status` 값. 기본 허용값은 정확히 `teacher`, `approved`다.
- 기존 Merge 앱의 클라이언트 설정, 콜백 목록, 운영 여부.
- 보물섬 운영 origin, 로컬 테스트 콜백, 현재 최고관리자인 김선생님의 Neobus `user_id`.

`admin` 유형을 교사로 자동 간주하지 않는다. 실제 관리자 계정이 `teacher`가 아니라면 사용자에게 그 사실을 알리고 해당 계정의 이용 정책을 정한 뒤 적용한다. 모르는 유형이나 승인 상태를 통과시키지 않는다.

### 4.2 클라이언트 등록의 기본 선택

이 계획의 기본은 **보물섬 전용 클라이언트 ID·시크릿을 분리**하는 것이다. 문서의 다중 클라이언트 방식으로 `treasure-island-v2`를 등록하고 기존 Merge 클라이언트를 유지한다.

- 비밀값이 포함되는 클라이언트 JSON 전체는 Cloudflare secret에 넣는다. 문서의 JSON 예시를 `wrangler.jsonc`의 공개 `vars`에 그대로 넣지 않는다.
- 클라이언트마다 표시 이름을 두고 인가 화면에 `보물섬 점령전 연결`을 표시한다. 클라이언트 ID를 추가해도 화면의 기존 `작품집 관리자` 문구가 자동 변경되는 것은 아니다.
- 인가 화면·코드 발급·토큰 교환에서 같은 클라이언트를 찾는지 확인한다. `/me`, `/revoke`에도 해당 구현의 클라이언트 구속 조건을 대조한다.
- 기존 클라이언트의 토큰·콜백·시크릿은 유지한다. 전역 쿠키/CORS 정책을 완화하지 않는다.
- 운영·개발 콜백을 정확히 등록한다. wildcard, 임의의 `returnTo`, 요청 Host에서 추론한 콜백을 사용하지 않는다.

Neobus 코드를 수정할 수 없는 상황이면 문서의 기존 클라이언트에 콜백만 추가하는 방식도 가능하다. 다만 이는 기본 설계의 변경이며, 시크릿 공유 및 기존 앱 영향·화면 문구를 실행 기록에 명시하고 운영 책임자와 공유한 뒤 선택한다. Neobus 준비가 막혀도 이 프로젝트 코드·백업 도구·로컬 검증은 먼저 완성할 수 있다. 준비되지 않은 상태에서 기존 계정을 삭제하지 않는다.

### 4.3 보물섬 설정

| 설정 | 용도 |
|---|---|
| `NEOBUS_ORIGIN` | 확인된 Neobus origin. 고정된 신뢰 대상 |
| `MERGE_CLIENT_ID` | 보물섬 전용 클라이언트 ID |
| `MERGE_CLIENT_SECRET` | secret으로 주입. 로그·문서·브라우저 응답에 금지 |
| `MERGE_REDIRECT_URI` | 정확한 운영 `/auth/callback` URL |
| `NEOBUS_SUPER_USER_IDS` | 김선생님으로 확인된 Neobus 고유 ID를 지정. 실제 ID는 아직 미확인 |

`SIGNUP_CODE`는 전환 뒤 제거한다. 관리자 지정은 이름이나 로그인 문자열로 추정하지 않는다. 누구든 첫 접속자가 관리자가 되는 동작도 금지한다.

최고관리자 승계 절차:

1. 기존 운영 DB에서 `is_super = 1`인 계정을 읽기 전용으로 확인하고 김선생님의 기존 ID를 복구용 기록에 남긴다. 사용자 설명과 다르거나 여러 계정이 있으면 임의로 승계 대상을 늘리지 말고 실제 대응을 확인한다.
2. 김선생님의 Neobus 계정을 신뢰할 수 있는 관리 조회 또는 본인의 인증된 로그인으로 확인하고 `user_id`와 교사·승인 상태를 확인한다. 표시 이름이 같다는 사실만으로 두 계정을 연결하지 않는다.
3. 확인한 Neobus 고유 ID를 `NEOBUS_SUPER_USER_IDS`에 등록한다. 예시 ID를 실제 값처럼 사용하지 않는다.
4. 기존 계정 삭제 전에 승계에 필요한 식별 정보와 설정 준비를 마친다. SSO 점검 단계에서 김선생님은 관제에 접근하고 다른 일반 교사는 접근하지 못하는지 확인한 후 서비스를 연다.

관리자 승계는 퀴즈 자동 이관과 별개다. 퀴즈는 이 문서의 CSV 백업·재업로드 방식으로 전달한다.

## 5. 인증·DB 구현 설계

### 5.1 파일별 작업

| 파일 | 작업 |
|---|---|
| `src/auth.ts` | 자체 인증 제거, SSO 세션 확인, 교사·관리자 권한, 로그아웃 |
| `src/neobus.ts` (신규) | PKCE 도구, token/me/revoke 통신, 응답 검증·타임아웃 |

### 5.2 데이터 모델

기존 데이터는 검증된 백업 뒤 정리하고 다음 스키마로 전환한다. 기존 `0001`~`0003`을 고쳐 적용 이력을 왜곡하지 않는다.

**teachers**

- `id TEXT PRIMARY KEY`: 새 내부 ID, 예: UUID. Neobus 로그인 문자열과 분리한다.
- `neobus_origin TEXT NOT NULL`, `neobus_user_id TEXT NOT NULL`.
- `UNIQUE(neobus_origin, neobus_user_id)`로 같은 신원의 중복 생성을 막는다.
- `display_name`, `created_at`, `last_login_at`, `is_super` 유지.
- `pw_salt`, `pw_hash` 제거. 가짜 비밀번호를 채우는 우회 구현을 하지 않는다.
- `is_super`는 확인된 Neobus ID 설정에 따라 갱신하며, 권한 검사에서도 설정을 확인한다. 설정에서 제거된 관리자가 오래된 DB 플래그로 계속 접근하면 안 된다.

**sessions**

- 브라우저에는 고엔트로피 임의 세션 ID만 HttpOnly 쿠키로 전달한다.
- DB에는 그 ID의 `token_hash`를 기본키로 저장한다. 교사 ID 외래키, `link_token`, 생성·만료 시각을 둔다.
- Neobus `link_token`은 서버에서 API 호출에 필요하므로 서버 저장소에만 보관한다. 브라우저·DO attachment·로그로 보내지 않는다.
- 로컬 세션은 최대 8시간이며 Neobus 응답의 토큰 만료를 넘지 않는다. timestamp 단위(초/ms/문자열)를 실제 계약에 맞게 변환한다.
- Neobus 신원과 교사 프로필 연결이 바뀌면 세션을 거절한다.

**login_transactions** (신규)

- 임의 트랜잭션 식별자, state, verifier, 생성·만료 시각. 수명 10분.
- 쿠키에는 식별자만 저장한다. 임의 외부 이동 주소는 저장하지 않는다.
- 콜백에서 `DELETE ... WHERE ... RETURNING ...` 같은 원자적 소비로 한 번만 꺼낸다. 별도 SELECT 후 DELETE를 단일 사용 보장으로 간주하지 않는다.
- 만료 검사를 매번 하고, 로그인 시 만료 행을 정리한다. D1에 KV처럼 자동 TTL이 있다고 가정하지 않는다.

**원격 revoke 재시도 기록**

- 로그아웃 때 Neobus가 응답하지 않아도 로컬 권한은 즉시 폐기한다.
- 남은 원격 토큰은 서버 전용 재시도 큐/테이블에 만료 시각과 함께 보관하고, 정기 작업에서 제한된 backoff로 revoke를 재시도한다. 성공하거나 원래 만료 시각이 지나면 삭제한다.
- 이 기록은 인증 가능한 세션이 아니다. 단순 `waitUntil()` 한 번만으로 재시도 보장을 주장하지 않는다.

### 5.3 스키마 전환의 실행 조건

기존 테이블은 비밀번호 NOT NULL 제약을 갖고 있다. 이번에는 비어 있는 `teachers`와 `sessions`를 새 정의로 재작성하는 전환을 사용한다.

1. 운영 점검 모드, 최종 백업 검증, 모든 기존 DO 정리가 먼저다.
2. 관련 데이터의 명시적 정리 후 `teachers`, `sessions`, `quiz_sets`, `rooms`, `game_records`가 모두 0행인지 확인한다.
3. 새 마이그레이션은 위 테이블 중 하나라도 비어 있지 않으면 **SQL guard가 실패하여 중단**되도록 만든다. 예를 들어 CHECK 제약이 있는 임시 가드 테이블에 전체 행 수를 넣어 0이 아닐 때 실패시키는 방식을 로컬 D1에서 검증한다. 단순 주석이나 셸 출력 확인만으로 보호하지 않는다.
4. 빈 `sessions`를 제거하고 빈 `teachers`를 재작성한 뒤 새 `sessions`와 인증 보조 테이블·인덱스를 만든다. 기존 자식 테이블의 `REFERENCES teachers(id)`는 유지한다.
5. migration의 원자성, 중간 실패, foreign key 검사 결과를 실제 D1 테스트 런타임에서 확인한다. `PRAGMA foreign_keys=OFF`에 기대지 않는다.

스키마 전환을 계정 삭제 대신 쓰지 않는다. 백업 없는 DB에 `migrations apply`만 실행해 데이터를 잃는 길이 없어야 한다. 새 빈 개발 DB는 기존 migration 전체 + 새 migration을 순서대로 적용할 수 있어야 한다.

### 5.4 인증 경로와 오류

| 경로 | 처리 |
|---|---|
| `GET /auth/start` | 암호학적 난수, S256 PKCE, 트랜잭션 저장, Neobus로 이동 |
| `GET /auth/callback` | 쿠키/state/만료 검증, 트랜잭션 1회 소비, 코드 교환, `/me`, 자격 검사, 프로필 upsert, 새 세션 |
| `GET /api/auth/me` | 로컬·Neobus 세션 확인 후 기존 화면 계약 `{ok,id,name,isSuper}` 유지 |
| `POST /api/auth/logout` | 로컬 세션 폐기, 쿠키 제거, 교사 소켓 권한 폐기, Neobus 연결 토큰 revoke |
| 기존 signup/login/password 경로 | 더 이상 인증을 수행하지 않음. 명확한 종료 응답(예: 410) |

교사 자격은 `/me`의 `success`, `data`, ID·이름·유형·승인 상태를 검증하여 판단한다. **응답이 200인 것만으로 교사로 인정하지 않는다.**

- 네트워크 호출은 제한 시간(초기값 5초)을 둔다.
- 401/폐기/만료: 로컬 세션을 무효화하고 재로그인 안내.
- 교사 아님·승인 안 됨: 403. 내부 프로필·샘플·세션 생성 전에 거절.
- 타임아웃·5xx·잘못된 응답: 503 등 일시 오류로 분리. 교사 기능은 거절하지만 일시 장애를 계정 삭제나 영구 로그아웃으로 바꾸지 않는다.
- 콜백 토큰을 받았으나 후속 단계가 실패하면 해당 토큰 폐기/재시도를 처리한다. 로그인 재시도는 새 state/verifier로 시작한다.
- 인증 응답은 `Cache-Control: private, no-store`, 콜백은 코드가 없는 내부 주소로 이동한다.
- 관측 로그에 콜백 query, Cookie, Authorization, token 응답 본문이 남지 않도록 앱 로그와 배포 로그 설정을 확인한다. 오류에는 비밀값 대신 요청 추적 ID만 남긴다.
- 쿠키는 HttpOnly, SameSite=Lax, 운영 HTTPS에서 Secure. tx 쿠키 Path는 `/auth`, 세션은 `/`.
- 변경 API의 Origin 검사 및 WebSocket 업그레이드 Origin 검사를 추가한다. 실제 게임 origin만 허용한다. OAuth 콜백은 state/PKCE로 검증하며 무조건 같은 Origin을 요구해 막지 않는다.

프로필 upsert는 같은 Neobus ID의 동시 첫 로그인에서도 하나만 생성한다. 최초 샘플 퀴즈도 한 번만 생성되도록 충돌 처리를 한다. 매 로그인마다 샘플이 늘어나면 안 된다.

### 5.5 열린 교사 WebSocket까지 권한 관리

현재 `teacherAtUpgrade` 값만 유지하는 구조는 수정해야 한다.

1. HTTP 교사 보호 경로는 로컬 세션과 Neobus 현재 신원을 재검증한다. 학생 요청은 Neobus를 호출하지 않는다.
2. DO에는 외부 요청이 조작할 수 없도록 Worker가 덮어쓴 내부 세션 식별자/해시를 전달한다. 브라우저 헤더의 교사 ID를 신뢰하지 않는다.
3. 교사 명령과 교사 전용 조회는 처리 직전에 검증한다. 같은 프로필의 다른 유효 세션이 있다는 이유로 폐기된 세션을 허용하지 않는다.
4. 연결이 조용할 때도 최대 30초 간격으로 교사 세션을 확인한다. 무효이면 교사 데이터 전송을 멈추고 연결을 종료한다. 따라서 Neobus 로그아웃을 서버 푸시로 즉시 감지한다고 설명하지 않는다. 다음 명령에는 즉시 재검증, 유휴 연결에는 최대 30초 확인 주기다.
5. Neobus 일시 장애에는 검증되지 않은 교사 명령·정답 전송을 허용하지 않는다. 학생들의 진행 상태를 지우거나 방을 폭파하지 않는다.
6. DO hibernation 뒤에도 세션 식별자와 만료가 복원되어야 한다. 검증 중 await 이후에는 방·세션·요청의 현재 상태를 다시 확인하여 닫힌 방에서 늦은 명령이 실행되지 않게 한다.
7. 기존 턴/방 정리 alarm과 인증 확인 alarm이 서로 덮어쓰지 않도록 다음 예약 시각의 최솟값으로 통합한다. 학생만 남으면 인증 확인용 반복 작업은 중단한다.
8. 소켓 재연결·HTTP 폴백도 같은 권한 기준을 쓴다. 인증 실패 때 화면이 무한 재접속하지 않도록 오류 코드를 구분한다.

이 앱에서 로그아웃하면 해당 앱 연결을 폐기한다. Neobus 전체 로그아웃을 대신 수행하는 기능으로 만들지 않는다.

## 6. 선생님별 CSV 퀴즈 백업

### 6.1 폴더 구조

작업 루트는 `보물섬점령전/backups/neobus-sso/실행시각_KST/`로 한다. 시각은 실제 실행 시 생성하고 이전 백업을 덮어쓰지 않는다.

```text
backups/neobus-sso/20260923_223000_KST/          # 시각은 예시
├── 전달용/
│   ├── 김선생/
│   │   ├── 엑셀모음/
│   │   │   ├── 국어1__quiz-12.csv
│   │   │   └── 사회1__quiz-18.csv
│   │   ├── 퀴즈목록.csv
│   │   └── 다시올리는방법.txt
│   └── 이선생/
│       ├── 엑셀모음/
│       ├── 퀴즈목록.csv
│       └── 다시올리는방법.txt
├── 운영복구용/                               # 선생님에게 전달하지 않음
│   ├── database-before-reset.sql
│   ├── source.sqlite                        # SQL을 가져온 로컬 검증 사본
```

- 모든 선생님의 폴더를 만든다. 퀴즈가 0개인 선생님도 목록에 `0개`를 표시한다.
- 동명이인이면 `김선생__기존아이디/엑셀모음/`처럼 구분하고 manifest에 실제 이름·기존 ID·경로를 기록한다.
- 파일명은 금지 문자·경로 구분자·제어문자를 치환하고 길이를 제한한다. 이름이 같거나 정규화 후 충돌해도 quiz ID로 구분한다. 저장 경로가 백업 루트 밖으로 나갈 수 없어야 한다.
- 제목은 원래대로 manifest와 퀴즈목록에 보존한다. 파일명의 `__quiz-ID`를 새 퀴즈 제목으로 그대로 쓰면 20자 제한에 걸릴 수 있으므로 재업로드 안내에 원래 제목을 적는다.
- 전달용 폴더에는 비밀번호 해시, 쿠키, 토큰, 관리자 전체 목록, 타 선생님 데이터가 들어가면 안 된다.
- `backups/`와 인증 세션 파일 경로는 생성 전에 `.gitignore`에 추가한다. Git 제외 상태를 확인한다. 복구용 폴더는 소유자만 읽을 수 있도록 권한을 제한한다.
- 영구 보존 위치는 위 폴더다. `/tmp`를 유일한 백업 장소로 사용하지 않는다.

### 6.2 백업 CSV의 내용과 범위

현재 앱은 업로드 원본 파일을 저장하지 않고 `items_json`을 저장한다. 백업 CSV는 **현재 등록된 문항·보기·정답을 재구성한 파일**이다. 업로드 때 제외된 행이나 원본 파일의 저장 형식까지 복원하는 것은 아니다. 이 사실을 전달용 안내에 적는다.

기존 `src/quizsets.ts`의 `toCsv`와 같은 형식을 사용한다. UTF-8 BOM을 포함한 `.csv` 파일을 생성하고, 그대로 이 프로젝트에 다시 업로드할 수 있게 한다. `엑셀모음`은 전달 폴더 이름이며 파일 형식은 CSV다.

### 6.3 추출·생성 도구

다음 도구는 아직 없으며 구현할 대상이다.

- `cloudflare-v2/tools/backup-neobus-quizzes.py`: 로컬 SQLite 사본에서 읽어 CSV·목록·manifest를 생성.
- `cloudflare-v2/tools/verify-neobus-backup.*`: 실제 앱 파서로 각 CSV를 다시 읽고 원본과 비교. 기존 Vitest Workers 런타임을 활용할 수 있다.
- Python 표준 라이브러리 `sqlite3`로 SQL을 로컬 사본에 가져오고, `csv`로 퀴즈 파일을 생성한다. 출력은 `encoding='utf-8-sig'`, `newline=''`, CSV 줄바꿈은 `\r\n`으로 지정한다. 별도 엑셀 생성 라이브러리는 필요 없다.

운영 조회를 반복해 교사별로 각각 다른 시점의 데이터를 섞지 않는다. **점검 모드에서 얻은 하나의 전체 SQL 스냅샷**을 기준으로 교사 목록·퀴즈·문항을 추출한다. SQL INSERT 문자열을 정규식으로 파싱하지 않는다.

조회에 필요한 주요 필드:

```sql
SELECT id, display_name, is_super, created_at, last_login_at
FROM teachers ORDER BY id;

SELECT id, teacher_id, title, items_json, item_count, source_name,
       skipped, problems_json, created_at, updated_at, used_at
FROM quiz_sets ORDER BY teacher_id, id;
```

퀴즈 소유자가 없는 행이 있으면 제외하지 말고 오류로 보고한다. 샘플 퀴즈도 등록된 퀴즈이므로 백업에 포함한다. 관리자 UI의 미리보기 5문항으로 백업하지 않는다.

### 6.4 CSV 작성 규칙

- 퀴즈 1개당 `.csv` 파일 1개. 인코딩은 UTF-8 BOM, 행 구분은 CRLF다.
- 첫 행은 `질문`, `정답`, `예제1`, `예제2`부터 시작한다. 기존 `toCsv`처럼 해당 퀴즈의 최대 보기 수에 따라 `예제3`, `예제4`를 추가한다.
- 쉼표·큰따옴표·줄바꿈이 있는 필드는 큰따옴표로 감싸고, 필드 안의 큰따옴표는 두 번 쓴다. 직접 문자열을 쉼표로 합치는 방식 대신 CSV writer를 사용한다.
- `q`와 `options` 원문을 보존한다. 앞에 작은따옴표 등을 덧붙이거나 줄바꿈·공백을 임의로 바꾸지 않는다. 검증은 스프레드시트에서 다시 저장한 파일이 아니라 생성된 CSV 자체를 기준으로 한다.
- 정답은 `ans + 1`의 십진수 문자열로 쓴다. 문항·보기 순서는 원본과 동일하다.
- 부족한 뒤쪽 보기만 빈 셀로 둔다. 보기 사이의 빈 값이나 4개 초과 보기를 임의 삭제하지 않는다.
- 저장된 원문이 현재 CSV 업로드 파서에서 동일하게 복원되지 않으면 오류로 중단하고 원본 JSON을 보존한다. 조용한 잘라내기·수정은 금지한다.
- 보기 2~4개, 정답 인덱스 범위, 문항 수, 문자열 타입을 검증한다.
- 등록 문항이 80개를 넘거나 파서가 문항을 버리면 정상 백업으로 판정하지 않는다. 원본을 보존하고 재업로드 방식부터 해결한다.

### 6.5 백업 합격 기준

`manifest.json`에 최소 다음을 적는다.

```text
실행 ID / 백업 시각 / Cloudflare 계정·DB 식별자 / 배포 버전
선생님 기존 ID·이름·폴더 / 교사별 퀴즈 개수 / 전체 문항 개수
퀴즈 ID·제목·소유자·문항 수 / CSV 상대경로 / 파일 SHA-256
정규화한 문항 배열 SHA-256 / 백업 도구·라이브러리 버전
```

다음 조건을 **모두** 확인한다.

1. 실제 교사 수가 사용자 설명과 일치하는지 확인한다. 3명이 아니면 실제 목록을 보고 원인을 확인하고 누락 없이 범위를 확정한다.
2. DB 퀴즈 수 = manifest 퀴즈 수 = 각 `엑셀모음/`의 퀴즈 CSV 수. `퀴즈목록.csv`는 퀴즈 파일 수에 포함하지 않는다. 교사별 합계도 일치한다.
3. 각 `item_count`와 `JSON.parse(items_json).length`가 일치한다.
4. **모든 퀴즈 CSV**를 현재 `parseCsv` → `parseQuizValues`로 읽는다. skipped=0, 문항 수 일치, `q/options/ans` 배열이 원본과 완전히 같아야 한다.
5. 한글·줄바꿈·따옴표·특수문자·수식처럼 보이는 문자열·2개/4개 보기를 도구 테스트로 확인한다.
6. 테스트용 SSO 교사로 각 전달 파일을 실제 업로드 경로에 올려 제목·문항·정답이 유지되는지 자동 검증한다. 운영 DB에 검증용 데이터를 넣지 않는다.
7. 전체 SQL을 **빈 복구 시험 DB**에 가져와 테이블·행 수·외래키·문항 해시를 대조한다. 로컬 SQLite 검사와 D1 가져오기 검사를 구분한다.
8. `verification.json`에 전체 결과가 PASS인 경우에만 삭제 단계로 넘어간다. 파일이 존재한다는 사실만으로 백업 성공으로 처리하지 않는다.

해시는 SQL·JSON·CSV 등 고정된 백업 파일을 대상으로 만든다. `checksums.sha256` 자기 자신이나 이후 계속 수정되는 `실행기록.md`를 검증 대상에 넣어 순환하거나 매번 실패하게 하지 않는다. manifest 생성과 검증 결과 작성 순서를 도구에 고정한다.

복구용 SQL에는 기존 인증 정보가 포함될 수 있으므로 그 원본은 제한된 복구용으로만 보관한다. 재운영할 복구 DB에서는 이전 세션을 다시 살리지 않는다.

## 7. 기존 데이터 정리와 전환 도구

### 7.1 점검 모드는 두 코드 버전 모두 지원

전환 전 기존 인증 버전과 전환 후 SSO 버전 양쪽이 동일한 점검 모드를 이해해야 한다.

- 일반 교사 로그인·가입·퀴즈 변경·방 생성 및 학생 신규 접속을 막고 점검 안내를 보인다.
- 이미 열린 WebSocket도 처리한다. HTTP 라우터만 잠그고 기존 교사 소켓이 DB/방을 변경하도록 두지 않는다.
- 정상 수업 종료 뒤 점검을 시작한다. 진행 중인 게임을 백업·복구 대상으로 약속하지 않는다.
- 운영 전환 도구는 일반 사용자 경로와 구분한다. Cloudflare 인증으로 배포한 임시 작업 Worker가 운영 D1과 기존 ROOM namespace를 명시적으로 바인딩하여 수행하는 방식을 기본으로 한다.
- 임시 Worker의 관리 명령은 강한 단기 secret과 작업 ID로 보호하고 공개 무인증 삭제 API를 만들지 않는다. 완료 뒤 임시 Worker·secret을 제거한다. 작업 ID·대상·결과만 기록하고 비밀값은 기록하지 않는다.
- 기존 ROOM 바인딩을 잘못 지정해 새 빈 DO namespace를 정리하고 성공으로 착각하지 않도록 script/class/namespace 실값을 검증한다.

### 7.2 DO를 먼저 정리하는 이유

D1의 교사나 방 행을 먼저 삭제해도 기존 DO의 퀴즈 사본·학생 정보·소켓은 별도로 남을 수 있다. 따라서 D1 방 목록을 잃기 전에 기존 방의 실제 내부 저장소를 정리한다.

1. D1 `rooms`의 모든 방번호를 파일에 저장한다. `ready`만이 아니라 `closed`, `provisioning` 등도 포함한다.
2. 해당 실제 ROOM 객체에 멱등 정리 RPC를 호출한다.
3. 성공 증거를 `rooms-close-results.json`에 방번호별로 기록한다. 실패·미확인 한 건이라도 있으면 DB 삭제를 진행하지 않는다.
4. 현재 `closeNow()`는 내부 `closeRoom()`이 D1 오류를 잡고 재시도 alarm을 예약한 뒤 **정상 반환할 수 있다**. 따라서 RPC가 resolve됐다는 이유만으로 완전 정리로 표시하면 안 된다.
5. 전환용 정리 RPC는 `closed / socketsClosed / storageCleared / alarmCleared` 등 실제 결과를 반환하도록 보완한다. 기존 생성자·ensureSchema가 빈 테이블을 다시 만들 수 있으므로 검증은 “게임 데이터·사용자 데이터·살아 있는 소켓·예약 alarm 없음”으로 정의한다.
6. 부분 실패 시 같은 방 정리를 재시도할 수 있어야 한다. 정리 도중 `rooms`를 지우지 않는다.
7. 자동 `sweepStaleRooms()`로 대체하지 않는다. 제한 개수와 오류 처리 때문에 전수 정리를 보장하지 않는다.

D1 목록에 없는 고아 DO까지 모두 제거했다고 단정하지 않는다. 목록 외 객체의 존재 가능성을 점검하고 확인 수단을 실행 기록에 남긴다. 증명이 어려우면 기존 namespace를 완전히 폐기하고 새 namespace로 전환하는 별도 작업이 필요한지 범위를 정한다. 그 판단 없이 namespace 전체 삭제를 실행하지 않는다.

### 7.3 D1 정리

일반 앱의 영구 기능으로 전체 삭제 버튼을 추가하지 않는다. 전환 전용 도구가 다음 조건을 검사한다.

- 점검 모드임.
- 실행 ID, 실제 DB ID, 백업 manifest의 대상이 일치함.
- 최종 백업의 행 수·내용 해시가 현재 데이터와 일치함. 닫기 작업으로 변하는 방 상태는 별도 비교한다.
- 백업 검증 PASS, DO 정리 전수 완료.
- 삭제 대상 교사 ID가 manifest에 명시되어 있고 미확인 새 계정·퀴즈가 없음.

정리 대상은 `sessions`, `game_records`, `rooms`, `quiz_sets`, `teachers`다. 자식부터 지우고 교사를 마지막에 지운다. 예상 대상 밖의 행이 있으면 중단한다. 기존 ID를 SQL 문자열로 이어 붙이지 말고 bind한다.

여러 삭제는 D1 `batch()`로 원자적으로 처리하고 결과를 기록한다. 단순히 `DELETE FROM teachers`를 실행해 CASCADE에 모든 것을 맡기지 않는다. 실패·중단 뒤 재실행 시 이미 정리한 단계와 아직 남은 단계를 식별한다. **SSO 사용자가 생성된 뒤에는 기존 초기화 단계를 다시 실행할 수 없도록** 완료 상태와 스키마 버전을 검사한다.

정리 직후 각 대상 테이블 0행과 외래키 검사를 확인한다. 그다음에만 SSO migration을 적용한다.

- [ ] 최종 D1 전체 SQL을 내보낸다. 이 스냅샷이 전달용 파일의 유일한 원본이다.
- [ ] 교사별 CSV·manifest·checksums·verification을 생성한다.
- [ ] 전체 파일 재파싱·업로드·SQL 복구 시험을 통과한다.
- [ ] 실패하면 점검을 풀어 기존 서비스를 유지하거나 원인을 해결한다. 삭제로 진행하지 않는다.

Wrangler 스킬과 현재 CLI를 확인한 뒤 사용할 내보내기 명령 형태:

```bash
# cwd: 보물섬점령전/cloudflare-v2
# 아래 경로는 생성한 실제 실행 디렉터리로 교체한다.
npx wrangler d1 export treasure --remote --output='../backups/neobus-sso/실제실행시각/운영복구용/database-before-reset.sql'
```

셸에 복사할 명령은 모든 실제 경로·대상을 확정한 뒤 실행 기록에 남긴다. 비밀값을 argv에 넣거나 `echo`로 출력하지 않는다.

### C. 정리·스키마·SSO 배포

- [ ] 백업 manifest에 기록된 기존 모든 방의 DO를 정리하고 내부 데이터·소켓·alarm 정리를 검증한다.
- [ ] 대상과 예상 수량을 다시 대조한 뒤 기존 D1 데이터를 정리한다.
- [ ] SSO migration을 적용한다. 실패하면 점검 모드를 유지하고 복구 절차로 간다.
- [ ] SSO secret·설정과 새 코드를 배포한다. 점검 모드는 유지한다.
- [ ] 제한된 점검 접근으로 실제 교사 로그인, 비허용 계정 거절, 관리자 권한, 퀴즈 업로드, 새 방·학생 입장·게임 종료를 확인한다.
- [ ] Neobus 로그아웃 후 HTTP/열린 WS 모두 교사 권한이 만료되는지 확인한다.
- [ ] 잘못된 client/콜백/secret에 대해 안전하게 실패하는지 비운영 환경에서 확인한다.
- [ ] 이상 없으면 점검 모드를 해제하고 Neobus 메뉴 연결을 공개한다.

제한된 점검 접근은 임시 관리 경로 또는 작업자 전용 접근 제어로 구현한다. 일반 계정을 백업 없이 다시 초기화하는 수단으로 사용하지 않는다.

### D. 전달과 마무리

- [ ] 사용자에게 `전달용/` 경로와 선생님별 퀴즈·문항 수를 알려준다.
- [ ] 사용자 전달용으로 각 선생님 폴더를 별도 압축할 수 있다. 다른 선생님 데이터나 운영복구용 폴더를 섞지 않는다.
- [ ] 선생님은 Neobus 로그인 → 퀴즈 보관함 → 업로드에서 `엑셀모음/`의 각 퀴즈 CSV를 그대로 올린다. 원래 제목은 `퀴즈목록.csv`를 참고하고, 목록 파일 자체는 퀴즈로 업로드하지 않는다.

- [ ] 요청 범위는 파일 전달 방식이므로 과거 이름을 근거로 새 계정에 자동 귀속시키지 않는다.
- [ ] 임시 운영 도구·점검 우회·단기 secret을 제거하고 기존 가입 secret도 정리한다.
- [ ] README와 실행기록, 이 문서의 상태·완료 체크를 갱신한다.

## 9. 테스트 및 회귀 기준

### 9.1 인증

- 정상 로그인, 이미 Neobus 로그인 상태, 미로그인 상태, 취소, 만료, state 누락·불일치.
- 동일 콜백 동시 요청·재실행은 한 번만 소비. 다른 브라우저의 tx 쿠키로 교환 불가.
- 학생·미승인·정지·알 수 없는 유형 거절. 교사 프로필·세션·샘플 생성 부작용 없음.
- 같은 Neobus 사용자의 동시 첫 로그인에서 프로필 1개·샘플 1개.
- Neobus ID와 로컬 프로필 불일치 거절, 이름 변경은 동일 신원에 반영.
- token/me/revoke 타임아웃·비정상 JSON·5xx 분리, 실패 후 새 로그인 가능.
- 관리자 allowlist 밖 접근 거절, 관리자 제거 즉시 반영, 비밀번호 재설정 종료.
- 쿠키 속성·Origin·CSRF·캐시·리다이렉트 검증. 브라우저에 link_token/verifier/secret 노출 없음.
- 두 탭의 로그인 시작이 겹쳐도 다른 계정으로 잘못 연결되지 않음. 이전 탭 실패 시 재시도 안내.
- 로컬 로그아웃·Neobus 로그아웃·승인 철회·세션 만료가 HTTP/WS/폴백에 반영.
- revoke 장애 후 로컬 권한은 즉시 없어지고 재시도 작업은 복구 후 정상 종료.

### 9.2 게임과 소유권

- 교사 A는 B의 퀴즈 다운로드·수정·방 제어 불가.
- 학생은 기존 방번호·이름 입장·재연결·정답 제출 유지. Neobus 장애가 학생 요청에 추가 의존성을 만들지 않음.
- 교사 세션 만료 후 새로 로그인하여 본인 방을 이어받을 수 있음.
- DO hibernation, 인증 중 방 종료, 재접속, 폴백, 턴 alarm과 인증 alarm 동시 발생.
- 교사 권한이 불명확한 동안 정답·관제 정보가 기존 소켓으로 계속 나가지 않음.
- 새 내부 UUID로 관리자 상세 경로가 동작. 기존 `[A-Za-z0-9]{4,20}` 정규식·UI 가정을 모두 점검.

### 9.3 데이터 전환

- CSV 백업 전수 round-trip 및 파일 SHA-256 검증.
- 백업 뒤 데이터가 바뀌면 정리 거절.
- DO 닫기 실패·D1 쓰기 실패를 성공으로 오인하지 않음.
- 빈 DB 전체 migration 성공, 데이터가 남은 DB에 전환 migration은 실패.
- 일부 단계 완료 후 재실행 가능. 새 SSO 데이터가 생긴 뒤 초기화 재실행은 거절.
- 전환 실패 시 백업으로 교사·퀴즈 복구 가능. 닫힌 진행 게임은 복구하지 않는다는 범위 확인.

### 9.4 기존 도구도 함께 수정

`test/auth.test.ts`뿐 아니라 `admin`, `rooms`, `room`, `quizsets`, `diagnose` 테스트의 signup 준비 코드도 바꾼다. 인증 자체 테스트는 실제 SSO 흐름과 모의 Neobus API를 통과시킨다. 게임 테스트 준비는 공통 fixture를 사용하되 운영에 테스트 로그인 우회를 만들지 않는다.

`tools/watch.mjs`, `watch-auto.mjs`, `playtest.mjs`, `stage.mjs`는 현재 비밀번호/가입코드 로그인을 사용한다. SSO 전환 후 그대로 두면 감시가 중단된다.

- 감시 도구는 브라우저의 정상 SSO 로그인으로 얻은 앱 세션을 제한된 파일로 전달하는 방식으로 갱신한다. 예: 작업자 전용 브라우저 프로필의 storage state에서 **해당 앱 쿠키만** 사용. Neobus 비밀번호·link_token을 CLI에 넣지 않는다.
- 파일 경로만 인자로 받고 권한 0600/Git 제외를 적용한다. 만료 시 재로그인 필요를 명확히 알리고 무한 재시도하지 않는다.
- 자동 플레이용 가상 계정은 로컬/격리 테스트에서 fixture로 준비한다. 운영 signup endpoint를 테스트 때문에 남기지 않는다.
- `watchauto-check.mjs`도 새 만료·재시도 동작을 검증하도록 수정한다.

기본 실행 명령(작업 디렉터리 `cloudflare-v2`):

```bash
npm run types
npm run check
npm test
node tools/freeze-check.mjs
node tools/steal-check.mjs
node tools/result-check.mjs
node tools/trap-check.mjs
node tools/watchauto-check.mjs
```

백업·migration·WS 인증 검증을 위 테스트에 추가한다. UI 초기화가 바뀌므로 실제 브라우저에서 Neobus 왕복과 교사 홈 진입도 확인한다. 자동 테스트 통과와 실제 Neobus 운영 연동 통과를 별도 기록한다.

## 10. 실패 시 복구

| 실패 시점 | 대응 |
|---|---|
| 백업·사전 검증 실패, 아직 삭제 전 | 기존 데이터 유지. 원인 해결 또는 점검 해제 |
| DO 정리 일부 실패 | 점검 유지, 실패 방 재시도. D1 삭제 금지 |
| 기존 DO 정리 완료, D1 정리 전 | 기존 계정·퀴즈로 복귀 가능. 과거 진행 방은 되살리지 않음 |
| D1 정리 또는 스키마 전환 뒤 실패 | 기존 코드만 rollback하지 말고 아래 DB 복구도 수행 |
| 새 SSO 사용자가 데이터를 만든 뒤 문제 | 그 데이터도 먼저 별도 백업. 전환 전 SQL을 덮어씌워 새 자료를 잃지 않음 |

DB 복구 기본 절차:

1. 점검 모드를 유지한다. 실패 시점의 현재 DB도 별도 백업한다.
2. 사전 시험을 통과한 전환 전 SQL을 **별도 빈 D1 복구 DB**에 가져온다. 바뀐 운영 스키마 위에 무작정 실행하지 않는다.
3. 행 수·퀴즈 내용·외래키와 migration 이력을 확인한다.
4. 복구 사본의 기존 `sessions`는 비운다. 이전 쿠키를 되살리지 않는다.
5. DO 정리로 이미 사라진 방의 행은 닫힌 상태로 정리한다. DB 복원만으로 진행 게임이 돌아온다고 안내하지 않는다.
6. 기존 인증 코드의 확인된 배포 산출물에 복구 DB binding을 연결해 점검 상태에서 배포한다. 기존 점검 전용 관리 도구는 일반 사용자에게 열지 않는다.
7. 교사 로그인·퀴즈 목록/다운로드·새 방 생성 확인 후 점검을 해제한다.
8. 실패 원인, 현재 활성 DB ID·배포 버전, 남겨 둔 원본/복구 DB를 실행 기록에 적는다. 복구 도중 원본 DB를 삭제하지 않는다.

완료된 게임·진행 중 게임의 DO 상태 복원은 이 계획의 보장 범위가 아니다. 이를 피하려고 수업 종료 후 전환한다. 복구용 DB와 별도 데이터의 최종 정리는 복구 성공 및 데이터 보존 상태를 확인한 뒤 수행한다.
